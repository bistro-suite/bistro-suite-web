# Cliente web de Bistro Suite

Cliente de Mithril 2 y Vite para Bistro Suite, junto a la aplicación histórica Cars Admin. Este directorio es la raíz del servicio web en Railway.

**Demo pública:** [bistro-web-production.up.railway.app](https://bistro-web-production.up.railway.app/). Incluye la carta pública y la ruta `/admin`. Las credenciales de administración para producción se configuran de forma privada y no se documentan aquí.

## Uso local

Requiere Node.js 24. Ejecuta `npm install` y luego `npm run dev`. `npm run build` genera `dist/`; `npm run start` sirve esa compilación en el puerto `$PORT` de Railway (4173 en local), admite la ruta de respaldo de la SPA y reenvía `/api`, `/sanctum` y `/storage` a `API_PROXY_TARGET`.

La carta consulta Laravel mediante `GET /api/v1/public/bistros/{slug}/menu`, usando el proxy de desarrollo `/api` de Vite. En Railway, el servidor Node reenvía `/api`, `/sanctum` y `/storage` por la red privada, de modo que las solicitudes del navegador y las cookies de Sanctum conservan el mismo origen y el API no necesita un dominio público. Configura `API_PROXY_TARGET` con la dirección HTTP privada del API y define `VITE_BISTRO_SLUG` al compilar. El Compose local usa el bistró `demo-bistro`; puedes seleccionar otro slug durante la compilación de Vite. Laravel consulta en PostgreSQL los productos de ese bistró y excluye los que no están disponibles. El catálogo de ejemplo incluye 16 platos ficticios disponibles en cinco categorías y un producto de prueba no disponible. Seis platos regionales del Norte de Santander tienen imágenes ilustrativas generadas para el menú. Las tarjetas, los modales de detalle, la búsqueda, los filtros por categoría y el carrito de sesión usan esta respuesta.

La carta de muestra reutiliza una imagen de comida y las fuentes Alegreya Sans de los repositorios antiguos. Su procedencia está documentada en [ASSET_PROVENANCE.md](./ASSET_PROVENANCE.md). La ruta `/admin` incluye inicio de sesión con cookies, administración de productos y una bandeja de pedidos recientes que permite buscar por referencia, nombre, teléfono y correo del cliente. Los filtros por estado muestran cantidades. Cada resumen abre el diálogo **Ver detalle del pedido**, con el contacto, destino, notas por artículo y desglose del total. El personal puede cambiar los estados permitidos desde la bandeja o el diálogo. La pestaña **Entrega y recogida** permite configurar cobertura, tarifa fija y dirección de recogida. El carrito público permite completar pedidos como invitado con los métodos habilitados, muestra el costo del domicilio y presenta una referencia de confirmación; no procesa pagos. Las credenciales de ejemplo del administrador están en el README del API y solo sirven para el entorno local de Compose.

Para ejecutar localmente el cliente en contenedor junto con Laravel, usa Compose según las instrucciones del [repositorio del API](https://github.com/bistro-suite/bistro-suite-api/blob/main/README.md). El contenedor de desarrollo Node 24 monta este directorio y sirve Vite en `http://localhost:5173/`.

Los platos, precios, cobertura de Centro/Caobos/La Riviera, tarifa de domicilio de $5.000 COP y dirección de recogida son datos ilustrativos. Antes de presentar la demo como un negocio real, cambia la configuración de entrega desde el panel. El carrito y su clave de idempotencia se guardan en `sessionStorage`: los refrescos y reintentos en la pestaña actual no crean un segundo pedido. Al editar el carrito se genera una nueva clave. El checkout envía los datos al API público, que vuelve a calcular los precios, valida el barrio configurado, aplica la tarifa y registra el pedido. Esta demo no incluye pagos, cálculo de impuestos, cuentas de clientes ni seguimiento público de pedidos.

## Railway

El servicio activo de Railway despliega este directorio desde la rama `main`, con `/modern-web` como directorio raíz. El servidor Node escucha en `$PORT` y usa `API_PROXY_TARGET=http://bistro-api.railway.internal:8080`, para mantener las solicitudes del API, Sanctum e imágenes subidas en el mismo origen público mientras el API permanece privado. La configuración adapta a esta aplicación la estructura del servicio frontend de `gestion-monitorias/frontend/railway.toml`. Mantén sincronizados el `railway.toml` del repositorio y los ajustes del servicio en Railway. Consulta la [referencia de configuración como código de Railway](https://docs.railway.com/config-as-code/reference).
