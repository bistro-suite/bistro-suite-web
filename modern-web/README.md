# Cliente web de Bistro Suite

Cliente de Mithril 2 y Vite para Bistro Suite, junto a la aplicación histórica Cars Admin. Este directorio es la raíz del servicio web en Railway.

**Demo pública:** [bistro-web-production.up.railway.app](https://bistro-web-production.up.railway.app/). Incluye la carta pública y la ruta `/admin`. El acceso guiado de solo lectura se habilita con las variables `VITE_ADMIN_DEMO_*` del servicio web; al habilitarlo, usuario y contraseña son públicos por diseño y deben corresponder a una cuenta aislada de demo.

## Uso local

Requiere Node.js 24. Ejecuta `npm install` y luego `npm run dev`. `npm run build` genera `dist/`; `npm run start` sirve esa compilación en el puerto `$PORT` de Railway (4173 en local), admite la ruta de respaldo de la SPA y reenvía `/api`, `/sanctum` y `/storage` a `API_PROXY_TARGET`.

La carta consulta Laravel mediante `GET /api/v1/public/bistros/{slug}/menu`, usando el proxy de desarrollo `/api` de Vite. En Railway, el servidor Node reenvía `/api`, `/sanctum` y `/storage` por la red privada, de modo que las solicitudes del navegador y las cookies de Sanctum conservan el mismo origen y el API no necesita un dominio público. Las imágenes regionales y las fuentes locales se sirven desde `modern-web/public/` y Vite las copia a `dist/` durante el build. Configura `API_PROXY_TARGET` con la dirección HTTP privada del API y define `VITE_BISTRO_SLUG` al compilar. El Compose local usa el bistró `demo-bistro`; puedes seleccionar otro slug durante la compilación de Vite. Laravel consulta en PostgreSQL los productos de ese bistró y excluye los que no están disponibles. El catálogo de ejemplo incluye 16 platos ficticios disponibles en cinco categorías y un producto de prueba no disponible. Seis platos regionales del Norte de Santander tienen imágenes ilustrativas generadas para el menú. Las tarjetas, los modales de detalle, la búsqueda, los filtros por categoría y el carrito de sesión usan esta respuesta.

La carta de muestra reutiliza una imagen de comida y las fuentes Alegreya Sans de los repositorios antiguos. Su procedencia está documentada en [ASSET_PROVENANCE.md](./ASSET_PROVENANCE.md). La ruta `/admin` incluye inicio de sesión con cookies, administración de productos y una bandeja de pedidos recientes que permite buscar por referencia, nombre, teléfono y correo del cliente. Los filtros por estado muestran cantidades. Cada resumen abre el diálogo **Ver detalle del pedido**, con el contacto, destino, notas por artículo y desglose del total. En modo demo se pueden consultar las secciones; al intentar escribir aparece un modal y el navegador no envía la acción. Laravel también rechaza escrituras administrativas con HTTP 403. La pestaña **Entrega y recogida** permite consultar cobertura, tarifa fija y dirección de recogida. El carrito público permite completar pedidos como invitado con los métodos habilitados, muestra el costo del domicilio y presenta una referencia de confirmación; no procesa pagos.

Para habilitar el acceso desde la carta, configura en Railway el servicio web: `VITE_ADMIN_DEMO_ENABLED=true`, `VITE_ADMIN_DEMO_READ_ONLY=true`, `VITE_ADMIN_DEMO_EMAIL`, `VITE_ADMIN_DEMO_PASSWORD` y, opcionalmente, `VITE_ADMIN_DEMO_MESSAGE`. Las variables `VITE_` se compilan en el navegador; usuario y contraseña serán públicos por diseño, así que usa una cuenta exclusiva para el demo. En el servicio API configura `DEMO_ADMIN_EMAIL` y `DEMO_ADMIN_PASSWORD` con los mismos datos, además de `ADMIN_DEMO_READ_ONLY=true` y opcionalmente `ADMIN_DEMO_READ_ONLY_MESSAGE`. El predeploy sincroniza la cuenta con el seeder. En entornos donde sí se permiten cambios, deja ambas variables `*_READ_ONLY=false`; el acceso guiado se puede deshabilitar con `VITE_ADMIN_DEMO_ENABLED=false`.

Para ejecutar localmente el cliente en contenedor junto con Laravel, usa Compose según las instrucciones del [repositorio del API](https://github.com/bistro-suite/bistro-suite-api/blob/main/README.md). El contenedor de desarrollo Node 24 monta este directorio y sirve Vite en `http://localhost:5173/`.

## Pruebas E2E

Con Node.js 24.8 o posterior, ejecuta `npm run test:e2e`. La suite usa Tester Army E2E con Chromium y simula las respuestas del API: verifica búsqueda y categorías, productos agotados, checkout de domicilio y recogida, recuperación ante validaciones del API, y la bandeja administrativa con confirmación y entrega de pedidos. No requiere credenciales ni crea pedidos en Railway. Los reportes y artefactos locales se guardan en `.e2e/`.

La exploración asistida puede buscar huecos de navegación con `npm run test:e2e:explore -- 'Explora la carta como cliente y busca problemas de navegación'`. Requiere configurar un modelo compatible con Tester Army. La exploración debe apuntar a un entorno local con datos ficticios; no usarla contra producción para completar formularios ni enviar pedidos. Su agente requiere un modelo y puede interactuar con la aplicación según las instrucciones de exploración.

Los platos, precios, cobertura de Centro/Caobos/La Riviera, tarifa de domicilio de $5.000 COP y dirección de recogida son datos ilustrativos. Antes de presentar la demo como un negocio real, cambia la configuración de entrega desde el panel. El carrito y su clave de idempotencia se guardan en `sessionStorage`: los refrescos y reintentos en la pestaña actual no crean un segundo pedido. Al editar el carrito se genera una nueva clave. El checkout envía los datos al API público, que vuelve a calcular los precios, valida el barrio configurado, aplica la tarifa y registra el pedido. Esta demo no incluye pagos, cálculo de impuestos, cuentas de clientes ni seguimiento público de pedidos.

## Railway

El servicio activo de Railway despliega este directorio desde la rama `main`, con `/modern-web` como directorio raíz. El servidor Node escucha en `$PORT` y usa `API_PROXY_TARGET=http://bistro-api.railway.internal:8080`, para mantener las solicitudes del API, Sanctum e imágenes subidas en el mismo origen público mientras el API permanece privado. La configuración adapta a esta aplicación la estructura del servicio frontend de `gestion-monitorias/frontend/railway.toml`. Mantén sincronizados el `railway.toml` del repositorio y los ajustes del servicio en Railway. Consulta la [referencia de configuración como código de Railway](https://docs.railway.com/config-as-code/reference).
